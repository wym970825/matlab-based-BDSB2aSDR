## 已知重点

1. 原捕获 codePhaseAbs 不是可靠的文件绝对编号，新增明确的 acqInputStartAbs/trackStartAbs。
2. 不将 FIR 延迟或预读长度加入 GNSS 观测时间；REACQ 回退使用逻辑样本索引。
3. 原 TrackResults2 使用循环缓冲、分块保存和属性分类，新增字段必须贯通。
4. IQ 门限使用各数据集 ADC 单位，TF 和 PB 不串联；旧配置未指定 Frontend 时保留原 EnablePB 行为。

## 实施中发现与修复

- 原初始化先按默认字节起点估计时长，可能在 JSON 覆盖前输出负的截断警告；现先应用采样率、位宽、IQ 路数和跳过字节，再估算可处理长度。新增回归检查。
- 新实验汇总初稿误读轻量 `ui_results.mat`，导致 PB 完成后停止编排；改读完整 `run_B2a_<tag>.mat`，从已有 PB 结果恢复汇总，不重复接收机计算。`short_01` 标明恢复原因，后续实验另建目录。
- MCP 捕获命令窗输出时 diary 文件可能为空；驱动现明确捕获并写入日志。新增每个 PRN 的逻辑时间进度文件，供长任务巡检。
- 保留旧 off/PB 对截断尾部的 EOF 行为，TF 模式严格拒绝残缺 IQ 文件。IFSource 在打开文件前验证偏移，避免构造失败泄漏句柄。
- 固定系数 FFT 缓存只缓存滤波器，不缓存信号或状态；三角核用两个长度 K 的滑动和等价计算。独立直接卷积、八种格式组合和实际短段均用于回归。
