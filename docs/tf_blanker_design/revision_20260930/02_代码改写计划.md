# 软件接收机 TF_Blanker_v1 代码改写计划

版本：R3，2026-09-30。本文仅描述下一阶段改写任务。本轮不执行这些改写；原程序、既有 MATLAB 实验脚本和五组配置均保留。新建的结果目录仅含独立设计验证与产物，不构成接收机升级。R3 支持 int8/int16 双路 IQ，采样率继承配置，抽头默认按基准换算。算法约束以 [算法设计报告](03_算法设计报告.md) 为准，参数选择依据见 [方案评估报告](01_方案评估报告.md)。

## 1. 范围与交付边界

第一阶段交付 v1：配置可选、独立前端、固定 -450 kHz 复 FIR、幅度检测、扩展平台/三角软边缘、精确样本对齐、捕获/跟踪/REACQ 一致读取、必要监测元数据，以及四组单星带宽比较。

不要求实时处理，不先写 MEX/GPU，不建立共享内存前端服务，不整文件生成巨大的复 double 中间数据。v2、IIR、在线带宽选择和新的 S4 校正模型均不在首阶段范围。

特别注意：当前 acquisition_robust_v2fft 内 codePhaseAbs 由捕获输入数组内的 boundaryAbs 和细码偏移计算；仅凭字段名不能认定它是整个 RF 文件中的绝对样本编号。当前普通跟踪主要以 skipNumberOfBytes 与 ch.codePhase 计算起点。实施时先固定现有语义，再增加 acqInputStartAbs / trackStartAbs 之类明确字段，不顺便改变捕获内部的码相位定义。

REACQ 的回退当前依赖底层 ftell/fseek。预读后的文件游标不再具有同样含义，必须改为使用逻辑末尾和原回退样本数计算新的绝对请求位置，而不是继续相对移动物理游标。重捕获输入缓存应标记为已经处理，不能再做一次 TF。

## 3. 配置契约

建议在原配置副本中增加以下字段；这只是文档中的未来契约：

~~~json
{
  "Frontend": {
    "mode": "tf_v1",
    "TF": {
      "centerHz": -450000,
      "stopbandWidthHz": 400000,
      "transitionEachSideHz": 150000,
      "firTaps": null,
      "referenceTaps": 641,
      "referenceSamplingFreqHz": 25000000,
      "kaiserBeta": 5.65326,
      "thresholdSource": "PB_settings.Th_static_tracking_or_Th_static",
      "thresholdAmplitude": null,
      "triangleSpanUs": 12,
      "pulseTailMarginUs": 2,
      "boundaryPolicy": "raw_with_invalid_flag"
    }
  }
}
~~~

mode 支持 off、pb、tf_v1；tf_v2 可保留为已知但尚未实现的枚举，选择它时明确报“未实现”，不能静默退回 v1。没有 Frontend.mode 时保持原 EnablePB 行为；显式 mode 是唯一选择，旧 PB 开关不再触发额外处理。

firTaps=null 或缺失时，采用 referenceTaps=641、referenceSamplingFreqHz=25 MHz，计算 D=max(1,ceil((referenceTaps−1)/2·fs/referenceSamplingFreqHz))、L=2D+1；若显式给出合法奇数 firTaps 则直接使用，不自动覆盖。运行记录保存请求策略、有效抽头、实际 D/K/P/H 和频响诊断。参考采样率只用于长度换算，实际 fs 仍来自现有 samplingFreq。

thresholdAmplitude=null 表示继承该数据集既有幅度门限，运行时必须解析为实际数值并保存；不把五组 int16 的 192.74 固化成 int8 默认值，不因位宽/采样率再次缩放门限。Fs、dataType、fileType 从现有设置取值；TF 只接受 fileType=2 且有符号 int8/int16，读取后转浮点但保留 ADC 数值。每复样本为 2·bytesPerValue，即 2/4 字节。非完整 IQ 偏移或文件尾部须明确报错。

验证内容：

- 中心/带宽/过渡带有限，带宽和过渡带为正；\(|f_c|+B_s/2+\Delta f<f_s/2\)。
- 参考抽头与显式抽头为大于等于 3 的奇数；参考采样率有限且为正；解析后的抽头及阈值有效。
- 三角窗和尾部裕量换算为整数样本并保存实际时长；K≥1、P≥0。
- 显式 tf_v1 仅接受上述双路 IQ；实数单路/其他位宽要明确拒绝，不静默退回另一模式。旧 off/pb 的输入能力不受此限制。
- H 由 D、K、P 推导，不能又让用户独立填写一个冲突延迟。

旧的 [frontend_design_proposal.json](../frontend_design_proposal.json) 和上轮仿真 JSON 属历史证据，仍含当时“单位待确认”等字段。本轮不改这些文件；未来实现以本契约和批复为准，不直接把旧草案作为运行配置。

## 4. 分阶段改写

### P0：冻结基线与确认行为

记录当前工作树和源码/配置哈希，保留用户已有修改。读取已有兼容性与算法测试，不覆盖旧结果。选取可重复的小段作为 off/pb 回归输入，确认现有正常跟踪与 REACQ 的样本编号语义。

产物：输入清单、基线结果、参数覆盖表。当前目录的只读哈希快照可作本轮审计，未来实施前仍需重新记录，不能假定环境永久不变。

恢复时已通过 26 项既有测试，包括算法诊断、导航数据间断、可选跟踪类、PLL 热噪声分支、伪距样本界限、闪烁强度定义及 NH 重捕获状态机。本轮未执行新的跟踪任务，不能据此把 P0 所需真实 off/pb 片段基线全部标为完成。

### P1：实现独立 v1 核心

建议新增 frontend/TFBlankerV1.m 和一个小型系数构造函数。核心接收带真实 halo 的原始 IQ 与绝对核心区间，返回处理后核心和统计。

直接采用算法报告的有限邻域参考实现；线性卷积可以使用 MATLAB 已有函数。不从调试目录直接调用上轮脚本作为生产模块，不把原型的隐式补零端点行为复制进生产。

完成权重归一化、平台证明对应测试、单侧频率、D 样本对齐、两种混合公式一致性。测试应能发现符号、一个样本偏移和循环卷积错误，而不只是重复实现公式。

设计实验已验证两个带宽的代数一致性、平台覆盖和延迟负对照，可作为独立参考。生产核心实现后仍须用其实际输出通过同样检查，不能把实验室通过状态直接复制成 P1/P2 完成。检测以 abs(x)>=T_A 为准；数学上等价的平方比较不能无条件保证浮点门限边界逐位一致。

### P2：实现离线 IFSource

建议新增 frontend/IFSource.m 与 createInterferenceMitigator 工厂。读取器负责 int8/int16 原始 IQ 解包、前后各 H 的数据上下文、逻辑游标、seek 与有效边界。保持原文件不变；处理后的浮点 IF 直接供相关器使用，不重新量化写回 int8/int16。

v1 支持 readRange、read、seekAbs、tellLogical。一个通道一个读取器即可；多星重复算相同区间得到一致结果是首版可接受的代价。可加小型连续块缓存，但缓存不得改变逻辑样本、统计口径或边界规则。

在 off/pb 模式保持原数据与原 PB 行为，TF 的 halo 和边界失效不能错误地强加给 off 模式。统计只计核心样本。

### P3：接入所有读取路径和时间映射

先改配置解析、路径、捕获包装和通道起点传播，再改普通跟踪、REACQ、probe 和其他正式入口。用 source.tellLogical 替换依赖物理 ftell 的观测时间获取；重捕获回退使用逻辑绝对索引。

跟踪环路、相关器和导航方程不放入滤波逻辑。除前端调用、样本来源、绝对索引、有效性传播和输出诊断外，不顺便重构算法。若发现独立 bug，单独记录和验证，避免带宽比较同时混入另一项算法变化。

### P4：保存监测诊断并完成短段回归

逐实际积分区间保存：

| 字段 | 定义 |
|---|---|
| frontEndMode / configHash | 处理模式和完整配置/系数身份 |
| detectorDuty | 核心检测 m 的平均值 |
| meanWeight / meanWeightSquared | 核心 w 和 w² 的平均值 |
| weightSupportFraction | 核心 w>0 的比例，数值零处理规则固定 |
| validCount / boundaryFlag | 有效核心样本数和边缘状态 |
| logicalStartAbs / logicalCount | 该积分的物理输入范围 |

不要把这些量全部装进旧 PDC。C/N0 和 S4 继续消费处理后相关量，原始 IF 总功率只作前端诊断。确有前端无效样本时，对相干积分/监测窗传播无效状态；不能补零后继续当作有效强度。

### P5：四组单星 A/B

新建实验驱动与配置副本，优先 PRN 11，useParfor=false、numberOfChannels=1、acqSatelliteList=[11]。关闭单星不需要的导航/NMEA/地图，保留跟踪与监测输出；这些覆盖项逐项保存，其余参数继承四个原配置。

先以短段检验捕获、时间映射和结果格式，随后完成每组 715 s 的 PB、TF400、TF600，建议附 off 对照。按组和模式串行执行，使用新的结果目录；支持失败记录和已验证任务跳过，不重复启动已有 MATLAB 任务。

每种模式独立经过相同前端的捕获与跟踪；如增设共同初始化实验，单独命名。单星有效输出与完整度是成功判据，导航解数不适用。按 [方案评估报告第 5 节](01_方案评估报告.md) 输出配对统计和带宽选择结论。

## 5. 必要验收矩阵

| 检查组 | 具体反例与通过条件 |
|---|---|
| 配置 | 旧 JSON 行为不变；显式 tf_v1 与 EnablePB=true 不双重处理；400/600 实际生效而非字段被忽略 |
| IQ 和单位 | int8/int16、I/Q 交织、非零 skip、每复样本 2/4 字节；门限 ADC 单位保持；+/-450 kHz 符号正确 |
| 采样率 | 25/30.69 MHz 的自动抽头及显式覆盖；K/P/H 不写死；新 fs 测频响；不能据前端测试宣称任意 fs 的整机跟踪均已支持 |
| 权重 | 单样本事件、长事件、脉冲对、重叠事件、跨边界事件；平台覆盖和范围正确 |
| 卷积/对齐 | 冲激、纯音、宽带复数据；双支路等于窄带扣除；对齐核心不含循环卷积污染 |
| 分块/seek | 不规则块、1 样本块、文件中部起点、反向 seek 后重读；有效区与整段参考一致 |
| 真正文件边界 | 不存在的前/后样本不参与有效统计；捕获裁剪保存真实起点；EOF 不追加人工样本 |
| REACQ | 重捕获缓存只处理一次；回退位置由逻辑索引确定；交接后时间和 Weil/载波重置规则保持一致 |
| 旧模式回归 | off/pb 捕获、Prompt、样本编号和原测试按适当容差保持一致 |
| 监测 | S4/C/N0 输入是处理后相关量；分块保存/加载前端有效性和统计无丢失 |
| 单星实验 | 四组×三个核心模式的完整结果，失败与覆盖率不被平均值隐藏；400/600 选择有证据 |

不为了优化吞吐重复扩大测试范围。数学不变量、已改变的入口和已知易错时序路径必须验证；与前端无关的模块按既有回归集检查即可。

## 6. 实验产物与可追溯性

每次运行保存原配置路径及哈希、显式覆盖、最终有效设置、前端系数、软件版本/工作树标识、MATLAB 版本、PRN、RF 原始范围、有效范围、状态和日志。按物理样本/文件时间对齐结果，不以曲线互相关的峰值去“修正”算法支路延迟。

评估表同时给出每种方法的完整率和公共有效交集；保存 pilot 与 total C/N0 的区别，以及 S4 窗的起止。上轮理想码代理数据不放进“真实单星跟踪结果”表。

本轮补充证据保存在 [review_20260930/design_review.json](../../../results/tf_blanker_design/review_20260930/design_review.json)。64 次合成数据比较支持继续保留 400 基准与 600 强干扰候选，不能与四组实测 dBm 条件对应或替代 P5。该目录的内存读取参考不具备生产配置、真实文件句柄和监测状态传播职责，不直接挪作 IFSource。

R3 的 [独立 IQ 对齐脚本](../../../results/tf_blanker_design/iq_alignment_20260930/verify_iq_fir_alignment.m) 已验证小型生成文件的读写、八种组合及负对照；详见 [简报](05_IQ格式与延迟对齐验证简报.md)。它不调用生产入口，未覆盖真实捕获/REACQ 交接与序列化，因此仍不能将 P2–P4 标记为完成。

最终交付包括可运行代码、回归结果、四组单星结果、带宽结论和已知限制。v1 通过后才能把 v2/IIR 作为独立研究任务安排；它们失败或未实施不妨碍对 v1 作出完整评价。
